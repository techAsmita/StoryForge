## What it does

1. **Describe an idea.** Protagonist, objective, genre, tone, an optional world rule and ending twist, plus plot dials for conflict, romance, action and length.
2. **The AI writes a structured story.** A pretrained Transformer LLM (Google Gemini) returns a title, logline, characters and relationships, six episode beats and the chapters, using one of four prompt-engineering strategies and your temperature / top-k / top-p settings.
3. **The AI draws it.** The LLM also writes four scene descriptions and a character sheet; a text-to-image model turns them into a four-panel storyboard.
4. **The app measures it.** Every prompt, setting, output and timing is saved. Automatic metrics and human ratings let you compare strategies and temperatures on the same idea.

The interface has four pages (**Create**, **Library**, **Explore**, **Settings**), and every story opens in a workspace with **Story**, **Scenes**, **Prompt Lab** and **Evaluation** tabs. The layout adapts to desktop, tablet and phone.

## Generative AI concepts (syllabus mapping)

| UCS748 topic | Where it appears in StoryForge |
|---|---|
| Large language models, Transformers | Stories are generated by Gemini, a pretrained Transformer LLM, through its API |
| Conditional text generation | Idea fields, genre, tone and plot dials are written into the prompt as explicit conditions |
| Sampling strategies | Temperature, top-k and top-p are passed to the model and compared in a temperature sweep |
| Prompt engineering | **Direct**, **Interview Pattern**, **Chain-of-Thought** (visible plan) and **Tree-of-Thought** (3 branches, scored, best one expanded); every prompt is shown in the Prompt Lab |
| Image generation | Scene prompts are rendered by a text-to-image model (OpenAI gpt-image, or Flux via Pollinations) |
| Multimodal generation | The LLM writes the scene prompts and a shared character sheet that drive the image model |
| Evaluation metrics | Distinct-1/2, brief coverage, character presence, length ratio, structure score and 1–5 human ratings |

## Run locally

Requirements: PostgreSQL, Python 3.12+, Node 20+. No deployment is needed; the app runs on your machine.

**1. Database** (run each line separately in pgAdmin or `psql`):

```sql
CREATE USER storyforge WITH PASSWORD 'storyforge';
CREATE DATABASE storyforge OWNER storyforge;
```

**2. Back end**

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                 # add your keys (see below)
uvicorn app.main:app --reload        # http://localhost:8000
```

Tables are created automatically on first start.

**3. Front end** (second terminal)

```bash
cd frontend
npm install
npm run dev                          # http://localhost:5173
```

**4. Tests:** `cd backend && pytest`

### Configuration (`backend/.env`)

| Variable | Purpose |
|---|---|
| `GEMINI_API_KEY` | Free key from [Google AI Studio](https://aistudio.google.com). Empty = demo mode with template text. |
| `GEMINI_MODEL` | Default `gemini-3.5-flash-lite` |
| `IMAGE_PROVIDER` | `openai` (best quality, paid per image), `pollinations` (free Flux) or `placeholder` (offline) |
| `OPENAI_API_KEY`, `OPENAI_IMAGE_QUALITY` | Used when `IMAGE_PROVIDER=openai`; quality `low`, `medium` or `high` |
| `POLLINATIONS_API_KEY` | Optional free secret key from enter.pollinations.ai; removes the 45 s wait between images |

`.env` is git-ignored. Never commit real keys.

Optional: regenerate the interface artwork with the configured image model: `python scripts/generate_art.py`.

## Experiments and results

`data/experiment_plan.json` defines the study: 3 story ideas × (4 strategies at temperature 0.9 + direct prompting at 0.3 and 1.5) = 18 generations.

```bash
cd backend && python scripts/experiments.py
```

Results are exported to `data/experiments/` (`results.csv`, `summary.json`, charts) and every generated story, with its prompts and metrics, to `data/samples/`.

| Strategies compared | Effect of temperature |
|---|---|
| ![](data/experiments/charts/strategy_metrics.png) | ![](data/experiments/charts/temperature_effect.png) |

The metrics are reference-free proxies (creative stories have no single correct answer, so BLEU or ROUGE against a reference would not be meaningful). See the report for the full analysis.


## API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | Live/demo mode and connected models |
| POST | `/api/stories/generate` | Generate and save a story |
| GET | `/api/stories` | Library |
| GET | `/api/stories/{id}` | Full story with prompts, scenes and metrics |
| PATCH | `/api/stories/{id}` | Favourite / human rating |
| GET | `/api/stories/{id}/related` | All runs of the same idea (comparison) |
| POST | `/api/stories/{id}/images/retry` | Retry failed images |
| DELETE | `/api/stories/{id}` | Delete a story and its images |
| GET / PUT | `/api/settings` | Generation defaults |

## Honest scope

StoryForge uses pretrained models through their APIs; we did not train or fine-tune a model. Our contribution is the system around them: conditional prompt construction, four prompting strategies, sampling control, the multimodal image pipeline, the evaluation framework and the experiments.
